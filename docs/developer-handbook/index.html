代码地图

入口层

apex/main.py 定义 CLI、dflow 查询命令和顶层分发；apex/__main__.py 是 console script 入口。

工作流层

submit.py 负责配置加载、上传目录、workflow 提交；flow.py 负责 dflow DAG、Step、Task 和监控。

科学核心层

common_equi.py 管弛豫；common_prop.py 管性质；property/ 放具体性质的任务生成和结果计算。

计算器层

calculator/ 按 VASP、ABACUS、LAMMPS 封装输入文件、势函数、任务文件列表和输出解析。

结果层

archive.py 写 all_result.json 和数据库；report.py 与 reporter/ 负责可视化。

测试层

tests/ 按 calculator、property、OP 和 fixture 分布；当前 CI 规范运行器是 coverage + unittest。

新增或修改性质

  1. 在 apex/core/property/ 找最接近的性质实现，确认目录形状、task_type、task_param 和 _compute_lower() 输出约定。
  2. 如果是新增性质，新增 property 类，并在 apex/core/common_prop.py::make_property_instance() 注册 type。
  3. 保持 property 层只处理性质科学逻辑；计算器输入/输出文件规则放在 apex/core/calculator/。
  4. 同步 README/examples 参数说明，必要时更新报告或 archive 对应展示。
  5. 补对应 tests/test_*.py，fixture 要覆盖任务目录、输入文件、结果解析和错误路径。

计算器与调度

计算器需求通常从 make_calculator() 开始定位，再进入 VASP、ABACUS 或 Lammps 类。输入文件生成、势函数复制、forward_files、backward_files 和 compute() 都应保持 calculator 层内聚。

VASP：tests/vasp_input/ 与 tests/equi/vasp/ 是主要 fixture。

ABACUS：STRU、赝势和轨道文件路径需要同步检查，避免只测试 POSCAR。

LAMMPS：模型文件、势函数文件和清理逻辑要同时检查本地路径与 OP retrieve 路径。

工作流与 dflow

影响 graph、artifact 或并发调度的需求，先读 FlowGenerator，再读对应 OP。 APEX 同时有本地 apex do 和 dflow OP 路径，二者共享科学核心但 artifact plumbing 不同。

本地路径main.py -> step.py -> common_equi/common_prop -> calculator/property
提交路径main.py -> submit.py -> flow.py -> op/* -> common_equi/common_prop
结果路径post_equi/post_property -> archive_workdir -> all_result.json -> report

归档与报告

archive_workdir() 是本地结果归档的中心；ResultStorage.sync_relax() 和 sync_props() 决定 all_result.json 的结构。报告入口是 report_local()， 它接受 workdir 或 JSON 文件，并交给 Dash report app 展示。

archive schema、输出目录名和公开 JSON 键属于用户可见契约。没有迁移计划时，不要改名、移动或静默兼容。

部署

这套手册是纯静态文件。为保证 AGENTS.md、CHANGELOG.md 和 docs/ 内文档都能离线访问，建议从仓库根目录启动静态服务器。 

uv run python -m http.server 8000 --bind 127.0.0.1

然后访问 http://127.0.0.1:8000/docs/developer-handbook/。 uv run python -m html.parser docs/index.html docs/developer-handbook/index.html 只做静默语法校验，不会启动网页服务。
